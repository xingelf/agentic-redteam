The Kerberos Attack Map

Active Directory's best-known attacks are not separate tricks — they are each an attack on one step of the same Kerberos exchange. Here is the three-party flow once; pick an attack and watch which message it cracks, which it skips, and which key it leans on. The pattern underneath is always the same: a key is a password hash, and a ticket is trusted by whoever can decrypt it.

An illustrative teaching model for authorized testing and defense. No tooling payloads, no target or engagement data. Each attack links to its write-up in the repo.

The flow is standard Kerberos: AS exchange → ticket-granting ticket, TGS exchange → service ticket, then AP-REQ to the service. Read the Kerberos authentication note for the full walkthrough.

Sources: MITRE ATT&CK (T1558 and sub-techniques), the repo's Active Directory security-basics notes. Representative, not exhaustive.
